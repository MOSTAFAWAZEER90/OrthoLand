# OrthoFlowAI - Project Description & Status Report
## AI-Powered Orthodontic Practice Management SaaS Platform

---

## 1. PROJECT OVERVIEW

**OrthoFlowAI** is a multi-tenant SaaS platform for orthodontic clinics. It manages patients, appointments, payments, treatment progress, AI-powered reports, photo management, communication, and more.

**Tech Stack:**
- Backend: ASP.NET Core 10 Web API
- Frontend: Blazor Web App (Server Interactive) + MudBlazor
- Database: PostgreSQL (via EF Core 10)
- Cache: Redis (StackExchange.Redis)
- Auth: ASP.NET Core Identity + JWT Bearer
- AI: OpenAI API integration
- Email: SendGrid
- Real-time: SignalR
- Architecture: Clean Architecture (Domain → Application → Infrastructure → API/Web)

**Target:** Premium SaaS similar to Notion/Stripe/Linear/HubSpot

## 6. ARCHITECTURE DECISIONS & NOTES

### Multi-Tenant Strategy
- **Shared database** with `ClinicId` discriminator
- EF Core Global Query Filter ensures clinic isolation
- `TenantMiddleware` extracts `ClinicId` from JWT claims and sets it on DbContext
- `SetClinicId()` method on DbContext for manual tenant context

### Identity Architecture
- Two user classes exist intentionally:
  - `ApplicationUser` (Domain) - Plain entity for the domain model
  - `ApplicationIdentityUser` (Infrastructure) - Inherits `IdentityUser`, used with ASP.NET Identity
- This keeps the Domain layer clean from Identity concerns
- `IdentityDbContext<ApplicationIdentityUser>` in Infrastructure

### Authentication Flow
- **API:** JWT Bearer tokens (stateless)
- **Blazor Web:** Cookie authentication + calls API with JWT
- `AuthStateProvider` in Blazor maps JWT claims to `ClaimsPrincipal`
- Login flow: Web → POST /api/auth/login → get JWT → store in session → use for API calls

### Service Registration Pattern
- Each layer has its own `ServiceRegistration.cs` with extension methods:
  - `services.AddApplication()` - AutoMapper, MediatR, FluentValidation
  - `services.AddInfrastructure(config)` - DbContext, Identity, JWT, Redis, all services

### Error Handling
- Global `ExceptionHandlingMiddleware` catches all exceptions
- Returns consistent `ApiResponse<T>` format with status codes
- `TenantMiddleware` for multi-tenant context
- `AuditMiddleware` for request logging

## 8. KNOWN ISSUES

1. **MudBlazor Warnings:** Several attribute names don't match MudBlazor v8.x API (Gutter, PanelClass, Active, RowHoverStyle). These are warnings only, not errors.

2. **SendGrid Package:** Using SendGrid 2.1.0 which has .NET Framework compatibility warnings. Consider upgrading to a newer version or using `SendGrid.Extensions.DependencyInjection`.

3. **AutoMapper Version:** AutoMapper 14.0.0 has a known vulnerability (GHSA-rvv3-g6hj-g44x). Consider upgrading.

4. **No EF Core Migrations Yet:** The API auto-migrates, but no migration files have been committed. Run `dotnet ef migrations add InitialCreate` to generate them.

5. **Frontend API Connection:** The Blazor Web connects to API at `https://localhost:7200/` by default. Make sure both are running.

6. **Seed Data Dependency:** The API auto-seeds on startup but requires a valid PostgreSQL connection first.
